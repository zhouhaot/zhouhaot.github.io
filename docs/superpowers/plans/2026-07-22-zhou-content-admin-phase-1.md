# zhou Content Admin Phase 1 Implementation Plan

**Goal:** Wire Decap CMS to the Phase 0 content model using GitHub App OAuth, deploy the admin panel as an independent Cloudflare Pages project, and establish a staging branch for draft previews before production merge.

**Architecture decisions (confirmed):**
- OAuth provider: GitHub App (client_id + client_secret web OAuth flow)
- Admin entry: `cms-admin/` directory → independent Cloudflare Pages project at `cms-admin` alias
- Preview strategy: staging branch → Cloudflare Pages branch preview; editorial workflow manages draft → in review → ready
- Source of truth for CMS fields: `CONTENT_CONTRACT` from Phase 0 (no independent field model in Decap)

**Constraints inherited from Phase 0:**
- `admin/` (legacy VOID.DEV) is untouched
- No content, credentials, or OAuth secrets in source; all secrets are Cloudflare env vars
- `CONTENT_CONTRACT` drives Decap config; Phase 1 may not independently restate names, defaults, enum values, directories, or extensions

## GitHub App Setup (User Action Required Before Task 3 Works)

1. Go to https://github.com/settings/apps/new
2. App name: `zhou-content-admin` (or similar)
3. Homepage URL: your production site URL
4. Callback URL: `https://<ADMIN_PAGES_URL>/oauth/callback`
5. Permissions:
   - Repository → Contents: Read & Write
   - Repository → Pull requests: Read & Write  
   - Repository → Metadata: Read (auto-set)
6. Generate a client secret (not the private key — that's for App-level API calls)
7. After creation, note: App ID, Client ID, Client Secret
8. Install the App on the `zhouhaot/zhouhaot.github.io` repository

Cloudflare Pages env vars to set on `cms-admin` project:
```
GITHUB_CLIENT_ID      = <App Client ID>
GITHUB_CLIENT_SECRET  = <App Client Secret>
```

## Task 3: OAuth Proxy (Cloudflare Pages Functions)

**Files:**
- Create: `cms-admin/functions/oauth.js`
- Create: `cms-admin/functions/oauth/callback.js`

**Flow:**
1. Decap CMS opens `/oauth?provider=github` in a popup
2. `functions/oauth.js` reads `GITHUB_CLIENT_ID` from env, redirects to GitHub's OAuth authorize endpoint
3. GitHub redirects to `/oauth/callback?code=<code>&state=<state>`
4. `functions/oauth/callback.js` exchanges code for token via GitHub's token endpoint using `GITHUB_CLIENT_ID` + `GITHUB_CLIENT_SECRET`
5. Returns `<script>window.opener.postMessage(...)` to pass the token back to Decap

**CORS / security:**
- `state` param is echoed back unmodified (Decap validates it)
- Token exchange happens server-side only (secrets never in browser)
- No credentials stored; token lives in browser memory only

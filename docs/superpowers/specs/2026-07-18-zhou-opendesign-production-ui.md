# zhou OpenDesign 生产 UI 规格

- 日期：2026-07-18
- 状态：已批准方向的生产化细化
- 原型来源：`F:\personalblog\Web-Prototype`
- 实现基线：`9bcb70f`

## 1. 产品目标

将 OpenDesign 的 Creative Lab 原型迁移为 `zhou` 的生产级个人作品集。站点首先证明 AI 应用开发、前沿 AI 工作流与企业 AI 转型落地能力，服务创业团队、中小企业与合作伙伴，同时支持求职转化。

第一转化是访问 GitHub 与查看可验证项目；第二转化是发起合作或求职沟通。不得以虚构案例、占位履历或未经授权的客户信息填充页面。

## 2. 品牌与内容规则

- 全站品牌只使用 `zhou`，删除 `LAB.LOG` 与 VOID.DEV 表达。
- 主张为“探索技术边界，让 AI 真正进入业务。”
- 对外身份为“AI 应用开发者”。
- 首页首先表达 AI 应用、Agent、RAG、工作流自动化、评估与部署；WebAR、AIGC 与视觉能力仅作为差异化补充。
- 不显示真实姓名、头像、学校、专业、年级、住址、电话等个人身份信息。
- 不保留“待补充”“项目占位”“真实姓名占位”等生产占位；无真实内容时展示明确空状态或隐藏模块。
- GitHub 使用已配置的公开地址。邮箱、简历、客户名、项目截图、指标与仓库只在确认可公开后加入。

## 3. 最终信息架构

公开一级导航：

- 首页 `/`
- 项目 `/projects/`
- 文章 `/articles/`
- 作品 `/portfolio/`
- 关于 `/about/`
- GitHub（站外主转化）

详情路由：

- 项目 `/projects/[id]/`
- 文章 `/articles/[id]/`

内部内容模型与公开路由解耦：

- `work` 映射为正式项目。
- `lab` 映射为首页实验模块，并可作为项目列表中的“实验”类型；不单独进入一级导航。
- `notes` 映射为文章。
- 新增 `portfolio` collection，按系列组织已确认授权的视觉或媒体作品。

新站尚未发布，因此不创建旧规划路由 `/work`、`/notes`、`/lab`。若上线前发现真实外链，再在部署层增加定向重定向。

## 4. 视觉系统

保留原型 Direction C 的技术编辑部 / Creative Lab 结构，但生产实现必须组件化，不直接复制页面 HTML。

- Light、Dark、Cyber 三套主题使用语义 token；Light 为基础，首次访问可跟随系统深色，Cyber 只能由用户主动选择。
- 色彩以 OKLCH 语义变量表达，并为关键前景/背景组合保留可访问对比度。
- 系统中文无衬线字体配合等宽元信息字体，不加载不必要的远程字体。
- 容器最大宽度 `1240px`，正文阅读宽度约 `720px`；桌面边距 `28px`，移动端 `18px`。
- 保留流式标题、Bento 网格、轻边框、克制阴影与状态点。
- 动效仅用于状态反馈、内容进入与导航关系；禁止粒子背景、鼠标光晕与普遍 3D 倾斜。
- 所有非必要动画响应 `prefers-reduced-motion`。

## 5. 页面要求

### 首页

Hero 明确 AI 应用开发定位、企业 AI 转型价值、GitHub 主按钮与项目次按钮。其后依次为精选项目、AI 能力地图、实验状态、交付方法、最新文章、当前状态与联系入口。没有真实内容的精选区必须隐藏或显示简洁空状态，不能渲染假卡片。

### 项目

项目卡展示类型、状态、年份、摘要、职责与技术栈。筛选由构建期渲染的数据驱动，客户端只控制已存在卡片的显示状态。正式项目与实验使用可辨识的类型标签，不把实验包装为客户项目。

项目详情固定叙事为：问题、约束、职责、方案、架构、关键实现、结果、局限与下一步。未提供的可选段落不渲染。

### 文章

列表支持搜索、标签筛选与列表/网格切换，且无结果时给出可恢复的空状态。详情页支持唯一锚点目录、阅读进度、代码复制、表格与上下篇；阅读区域不使用干扰性的玻璃效果或持续动画。

### 作品

按系列策展，不使用密集瀑布流。无已确认媒体时只呈现真实空状态。真实媒体必须提供尺寸、alt、caption、许可状态与按需加载；灯箱支持键盘、Esc、左右切换与焦点陷阱。

### 关于

仅使用匿名职业资料：定位、能力范围、工作方法、当前求职/合作状态和公开联系入口。不实现真实姓名、学校或私人经历字段。

## 6. 交互与响应式

- 桌面顶栏；`<768px` 使用移动抽屉与五项底部导航。
- 移动抽屉具备遮罩、Esc 关闭、焦点返回、`aria-hidden` 与 `inert` 状态。
- 主题选择持久化且避免首屏主题闪烁。
- 项目筛选支持左右方向键；文章筛选与复制结果通过 `aria-live` 宣告。
- 文章目录在 `<920px` 切换为折叠形式；所有锚点唯一。
- 首页在 `<1024px` 重排为单列；卡片与内容在 360px 起无横向滚动。
- 验证宽度：360、390、430、600、820、1024、1366、1440、1920。

## 7. 技术边界

- Astro、TypeScript strict、Content Collections、Markdown/MDX、静态生成。
- 轻交互使用原生 TypeScript 模块，不为主题、筛选、抽屉、复制或灯箱引入 React/Vue。
- 第一阶段无数据库、CMS、账户、评论、订阅或运行时内容 API。
- 样式拆分为 token、base、components 与页面 scoped CSS；禁止把原型的大段内联样式原样搬入页面。
- 图片使用 Astro assets / `Image` 管道；构建时验证内容 schema 与公开 URL。

## 8. 质量门

- `npm run format:check`、`npm run lint`、`npm run check`、`npm test`、`npm run build` 全部通过。
- Playwright 覆盖首页、项目、文章、作品、关于、404、GitHub 主转化、主题、移动抽屉、筛选、搜索、目录、复制与灯箱。
- Axe 不得出现 serious 或 critical 级别问题；仅键盘可完成所有交互。
- 所有验证视口无横向溢出；桌面与移动关键页保留视觉回归基线。
- 生成 canonical、OG、RSS、sitemap、robots 与正确的 JSON-LD。
- 发布前扫描个人信息、占位文本、无效链接、未授权媒体和未经证实的结果指标。

## 9. 对旧计划的影响

原 foundation 计划 Tasks 1–4 已完成。Tasks 5–8 不再按原路由直接执行：

- 原 Task 5 由新的公开路由与内容适配任务替代。
- 原 Task 6 的 RSS、sitemap、robots 与结构化数据保留，但路径改为 `/articles`、`/projects`、`/portfolio`。
- 原 Task 7 扩展为完整原型交互、可访问性与多视口验收。
- 原 Task 8 的 CI 门保持不变，并在新 UI 完成后执行。
